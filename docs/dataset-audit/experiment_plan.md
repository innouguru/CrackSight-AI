# Experiment Plan

Derived from `project_vision.md` (baseline crack detection on painted/unpainted walls, free data + open-source tooling) and the audit findings in this directory.
Created: 2026-10-25. Dataset status: **PASS WITH CONDITIONS** (C1–C6).

---

## 1. Objectives

| # | Objective | Success signal |
|---|---|---|
| O1 | Establish a reproducible crack-**segmentation** baseline on the three public datasets | Beats trivial all-background predictor on every split, with full per-dataset metrics reported |
| O2 | Quantify cross-dataset generalisation (façade ↔ pavement ↔ concrete) | Per-dataset train/test matrix, gaps measured and explained |
| O3 | Decide whether the available data supports the vision's *measurement* tasks (length/width/orientation) | Mask quality + resolution analysis: minimum crack width representable per dataset |
| O4 | Decide whether an auxiliary crack/no-crack **classifier** and **detector** add value | Classification AUC and detection mAP vs segmentation-derived baselines |
| O5 | Produce an honest data-sufficiency verdict for severity assessment | Written conclusion citing measured coverage, sample counts and domain gaps |

Explicit non-goals for this phase: no new data collection, no custom hardware, no claim of structural safety (vision safety boundary).

## 2. Data strategy (audit decisions applied at ingestion)

### 2.1 Common ingestion rules (from `engineering_decisions.md`)

| Rule | Source decision |
|---|---|
| Canonical target = binary raster mask `{0,1}`, class `0 = crack` | DSET-003, DSET-004 |
| concrete400 masks binarised at `> 127`; threshold recorded per run | DSET-003, C4 |
| Remove byte-identical duplicates (keep one per digest); never modify source files | DSET-006, C3 |
| Report sample counts as **unique views** for façade (87 train / 21 valid, not 260/21 files) | DSET-002, C2 |
| Project-side config carries corrected crack-seg counts (val 200 / test 112) | DSET-009, C5 |
| Façade data is internal-only until its licence is resolved | DSET-008, C6 |

### 2.2 Splits

| Dataset | Split used | Size (measured) | Notes |
|---|---|---|---|
| crack-seg | `train` / `val` / `test` as shipped | 3,717 / 200 / 112 | source-ID clean (0 shared IDs); exclude the duplicate `test/1979…` image → scored test = 111 |
| concrete400 (seg) | README ID ranges: `image_001–303` / `image_304–379` | 303 / 76 | materialise as a manifest file, folders untouched |
| concrete400 (cls) | cluster-aware split (dHash ≤ 6 clusters kept intact), stratified to 633/869 balance | ~80/20 of 1,502 patches | satisfies README's leakage warning; cluster manifest recorded |
| façade | **scene-grouped** split: group key = scene id without `_v<N>` | 36 scenes train / 15 scenes valid (87 + 21 views) | C1; shipped folder boundaries used only as a disclosed fallback |

Every manifest file records: file path, split, source view, scene key, dataset, duplicate-digest group. Manifests are regenerated by script, never hand-edited.

### 2.3 Leakage controls

1. Verify 0 scene/source-ID overlap across splits after manifest creation (assertion in the data loader).
2. Exact-digest groups never span splits (assertion).
3. Evaluation runs only on de-duplicated images; denominators logged.
4. The 6 strong cross-split crack-seg near-duplicate pairs are visually inspected before any published crack-seg number (RISK-05); excluded if confirmed same surface.
5. Augmentation is applied **after** splitting, on-the-fly, never by pre-generating variants into the dataset (avoids repeating the façade variant mistake).

## 3. Preprocessing

- **Resizing:** train at native resolution per dataset (416 / 512); for joint training use 512×512 with aspect-preserving padding; record the choice (RISK-03).
- **Mask rasterisation:** polygons rasterised at 2× then downsampled to preserve hairline connectivity.
- **Normalisation:** per-channel mean/std computed on the training split only, per dataset.
- **Class imbalance:** report both image-level and pixel-level statistics; use Dice/Tversky or focal+BCE (chosen per baseline run, recorded).
- **Empty annotations:** the one all-background façade mask and the one empty crack-seg label are *retained* in training (legitimate negatives) and reported separately in evaluation.

## 4. Baselines and models

All open-source, CPU/GPU-portable (budget constraint).

| ID | Model | Purpose |
|---|---|---|
| B0 | Trivial all-background / thresholded-contrast predictor | Floor: any model must beat this on Dice/IoU |
| B1 | U-Net (ResNet-34 encoder, ~20M params) | Primary baseline, trains on modest hardware |
| B2 | DeepLabV3+ (MobileNetV3) | Lightweight comparison, edge-deployability proxy |
| B3 | SegFormer-B0 | Capacity upper bound for this data size |
| B4 | Same as B1 but trained per-dataset | Isolates negative transfer (DSET-007) |
| C1cls | Small CNN classifier on concrete400 patches | Objective O4 |
| D1det | YOLO-format detector on concrete400 boxes | Objective O4 (optional, boxes→YOLO conversion documented in README) |

## 5. Metrics

| Level | Metrics | Why |
|---|---|---|
| Pixel | Dice/F1, IoU, precision, recall (crack class) | Standard segmentation comparison; Dice tolerates imbalance |
| Image | per-image Dice distribution (median, IQR, worst decile), % images with Dice = 0 | exposes catastrophic misses hidden by means |
| Structure | connected-component count error, skeleton length estimate error | prerequisite for the vision's length/width measurements (O3) |
| Classification | accuracy, balanced accuracy, ROC-AUC, confusion matrix | 633/869 imbalance → balanced metrics primary |
| Detection | mAP@0.5, mAP@0.5:0.95 | comparison with published detectors |
| Calibration | reliability curve / ECE on crack probability | severity assessment later needs trustworthy confidence |
| Efficiency | params, latency, VRAM | deployment realism |

**Reporting rule:** every result table carries per-dataset, per-split columns (DSET-007). No single pooled score stands alone. Empty-mask images are listed separately.

## 7. Protocol and reproducibility

- **Seeds:** fix and log Python/NumPy/framework seeds; 3 seeds per headline configuration, report mean ± std.
- **Selection:** early stopping on val Dice only; `test` touched once per configuration.
- **Environment:** project `.venv` (Python 3.12.5), versions recorded in results files.
- **Artifacts per run:** config YAML, git-free run id, manifest hash, dataset byte-fingerprint (477,182,172 B baseline), metrics JSON, sample overlays (image | GT | prediction).
- **Assertions at load time:** pair counts (281 façade / 4,029 crack-seg / 379 concrete400), split disjointness, class schema = binary.
- **Human review:** every headline claim reviewed against the overlay panels, not just the numbers.

---

## 8. Acceptance criteria (phase gate)

The phase is *passed* — and the vision's next phase (measurement/severity) is *greenlit* — only if **all** hold:

1. B1 beats B0 on every split with Dice margin ≥ 0.10 and ≥ 90% of non-empty images scored Dice > 0.
2. Per-dataset metrics are reported and no dataset shows median Dice < 0.30.
3. E3 shows the façade scene-grouped score within the reported interval (if the gap is > 0.10 Dice, façade numbers are flagged as leakage-inflated and excluded from claims).
4. E6 shows threshold sensitivity < 0.05 Dice (else masks are declared unfit for measurement claims — RISK-03 becomes a blocker for O3).
5. All manifests pass the disjointness assertions; test set evaluated exactly once per configuration.
6. Licence status for façade resolved (DSET-008) before any public release of results.

**Verdict template for O5:** "The data supports / does not support the measurement tasks because ⟨E9 numbers⟩; severity assessment is / is not defensible because ⟨calibration + sample-size evidence⟩."
